[PostgreSQL](https://www.postgresql.org/) is a relational database; with the [pgvector](https://github.com/pgvector/pgvector) extension it stores embeddings next to application data. Vane upserts query results by key through distributed ADBC bulk loads, so rerunning a pipeline updates existing rows instead of adding duplicates.

## Example

This example writes two products to `products`. Install the `vane-ai[postgres]` extra, enable pgvector, and create the target table with `id bigint PRIMARY KEY`, `title text`, and `embedding vector(3)`. Set `POSTGRES_PASSWORD` to the database password in every worker's environment.

```python
import vane
from vane import EnvironmentSecret, PostgresSink

relation = vane.sql("""
    SELECT id, title, embedding
    FROM (VALUES
        (1, 'Red running shoe', [0.12, 0.85, 0.33]),
        (2, 'Blue rain jacket', [0.91, 0.08, 0.27])
    ) AS products(id, title, embedding)
""")

sink = PostgresSink(
    "products",
    dsn="postgresql://writer@db.example:5432/app",
    password=EnvironmentSecret("POSTGRES_PASSWORD"),
    key_columns="id",
    worker_count=2,
)
summary = relation.write_datasink(sink)
```

The table needs a primary key or unique constraint on the key columns, whose values must be non-null and unique in the input. Values are cast to the target column types, including `uuid`, `jsonb`, and `vector`; map input names to other column names with `field_mapping`. Each batch commits in its own transaction, so a rejected value rolls back only that batch, and writing the same keys again replaces the earlier values.

`dsn` is a libpq connection string or URI and must not contain the password. Pass the password as `password=EnvironmentSecret(...)`; it is read on each worker. Omit `password` when the server does not require one, for example with certificate authentication.
