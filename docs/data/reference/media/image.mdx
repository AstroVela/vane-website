---
title: Image functions
---

Image functions decode, inspect, transform, and encode `IMAGEFILE` and `IMAGE` values. Each function has a Python form, an `Expression` method form, and a SQL form sharing the same arguments. The connection's `image_backend` (`python` by default, `native` with the loaded `native_media` extension) selects the Pillow/tifffile/imagecodecs path or the C++ path; `EXPLAIN` shows `native_*` names for native plans.

## Signatures

```python
vane.image_file_metadata(value, *, max_bytes=..., max_pixels=...) -> Expression
vane.decode_image_file(
    value, mode=None, on_error="raise",
    *, max_input_bytes=..., max_pixels=..., max_decoded_bytes=...,
) -> Expression
vane.decode_image(bytes_expr, on_error="raise", mode="RGB") -> Expression
vane.crop(image, bbox) -> Expression
vane.resize(image, w, h, *, antialias=False) -> Expression
vane.convert_image(image, mode) -> Expression
vane.encode_image(image, image_format) -> Expression
vane.image_hash(
    image, *, method="phash", hash_size=8, binbits=3, segments=3,
) -> Expression
vane.image_to_tensor(image) -> Expression
```

SQL forms are `image_file_metadata(file)`, `decode_image_file(file, mode => ..., on_error => ...)`, `decode_image(bytes, ...)`, `crop(image, bbox)`, `resize(image, w, h)`, `convert_image(image, mode)`, `encode_image(image, format)`, `image_hash(image, ...)`, and `image_to_tensor(image)`. `mode=None` in `decode_image_file` preserves source modes already representable by `IMAGE`; `decode_image` defaults to `IMAGE('RGB')`.

## Parameters

| Name | Type | Description | Default |
| --- | --- | --- | --- |
| `value` / `image` / `bytes_expr` | `IMAGEFILE` / `IMAGE` / `BLOB` value or `Expression` | Input to inspect, decode, or transform | Required |
| `mode` | Mode name, `ImageMode`, or `Expression`; `None` allowed for `decode_image_file`/`convert_image` | Result pixel mode; `None` preserves (file decode) or keeps (convert) the input mode | `None` (`decode_image_file`), `"RGB"` (`decode_image`) |
| `bbox` | `(x, y, width, height)` integer tuple/list or `Expression` | Crop origin with positive width and height; out-of-input pixels are zero-filled | Required |
| `w` / `h` | Positive integer, `Expression`, or `None` | Resize target width/height; constant dimensions with a known mode yield a fixed-shape result; `NULL` produces `NULL` | Required |
| `antialias` | `bool` or `Expression` | Widen the triangle filter during downsampling when `True` | `False` |
| `image_format` | `ImageFormat` member, format string, or `Expression` | `PNG`, `JPEG`, `TIFF`, `GIF`, or `BMP` under the mode matrix below | Required |
| `method` | Hash method name (constant) | `ahash`, `dhash`, `dhash_vertical`, `phash`, `phash_simple`, `whash`, `colorhash`, or `crop_resistant` | `"phash"` |
| `hash_size` | Integer constant, `2`–`64` | Hash grid size; `whash` requires a power of two | `8` |
| `binbits` / `segments` | Integer constants, `1`–`8` / `1`–`16` | Color-bin bits and crop-resistant grid segments | `3` / `3` |
| `on_error` | `"raise"` / `"null"` | `"null"` suppresses only classified media format and codec failures | `"raise"` |
| `max_bytes`, `max_pixels`, `max_input_bytes`, `max_decoded_bytes` | Integer or `Expression` | Bounded header/probe and decode budgets | Backend defaults |

`encode_image` follows an explicit mode matrix: PNG accepts all eight integer modes; TIFF accepts all ten; JPEG accepts L/RGB; GIF accepts L/RGB with at most 256 palette colors; BMP accepts L/RGB. Use `convert_image` first for other combinations.

## Returns and errors

`image_file_metadata` returns a metadata `STRUCT` without decoding pixels. `decode_image_file` and `decode_image` return `IMAGE` (dynamic, or `IMAGE(mode)` for a constant mode). `crop` returns a dynamic image retaining the input mode constraint. `resize` with constant dimensions and a known mode returns a fixed-shape image. `encode_image` returns encoded `BLOB` bytes. `image_hash` accepts all image modes and returns `FIXEDBINARY(n)` content-similarity bits (MSB-first, zero-padded in the last byte), not an integrity checksum; hash options must be non-`NULL` constants. `image_to_tensor` returns an HWC `TENSOR` preserving pixel values; it belongs to the base engine and needs no image backend.

`NULL` inputs produce `NULL`. Invalid coordinates, modes, formats, resource-limit breaches, missing codec dependencies, and cancellation propagate as errors. Each operator accepts at most 100 million pixels and 256 MiB of pixel data per input image.

## Example

```python
import vane

con = vane.connect()
result = con.sql("""
    SELECT encode_image(
        crop(decode_image_file(image_file('photo.png'), 'RGBA'), [10, 20, 64, 48]),
        'PNG'
    ) AS thumbnail
""").fetchall()
vane.close()
```

The query returns one row with the PNG-encoded thumbnail bytes.

Native execution of the same query:

```python
import vane

con = vane.connect()
vane.load_installed_extension("native_media", connection=con)
con.execute("SET image_backend = 'native'")
con.sql("SELECT image_file_metadata(image_file('photo.png'))").show()
```
