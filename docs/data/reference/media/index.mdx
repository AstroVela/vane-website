Vane processes images, audio, and video through a unified type system with two execution backends per domain. Use this reference to choose an API and check its signatures, parameters, return values, and errors. Expression calls return a lazy `vane.Expression`; name it with `.alias(...)`. SQL calls are projection expressions and use `AS` to name their result.

## Domains

- [Image functions](image/index.mdx): decode, inspect, transform, and encode `IMAGEFILE` and `IMAGE` values.
- [Audio functions](audio/index.mdx): inspect `AUDIOFILE` metadata and resample waveforms.
- [Video functions](video/index.mdx): stream decoded frames as rows and build or inspect reusable seek indexes.
- [Multimodal types](../types.mdx): `FILE`, `IMAGE`, and `TENSOR` storage and value contracts.
- [Tensor functions](../tensor.mdx): construct and inspect `TENSOR` values.

## Backends

Each domain selects its execution backend independently through `image_backend`, `audio_backend`, and `video_backend`. All three settings default to `python` and accept only `python` or `native`.

| Backend | What it uses | What to install |
| --- | --- | --- |
| `python` | Pillow/tifffile/imagecodecs for images, SoundFile/SoXR for audio, PyAV for video | `vane-ai[image]`, `vane-ai[audio]`, `vane-ai[video]` |
| `native` | The optional `native_media` C++ extension (FFmpeg, libsndfile, SoXR) | The `vane-extension-native-media` provider wheel |

```python
import vane

con = vane.connect()
vane.load_installed_extension("native_media", connection=con)
con.execute("SET image_backend = 'native'")
```

`image_to_tensor` and the `IMAGE` accessors belong to the base engine and require no optional extension, regardless of the selected backend.
