---
title: Multimodal types
---

Vane carries multimodal data as typed engine values: the `FILE` family for immutable object references, `IMAGE` for decoded pixels, and `TENSOR` for numeric arrays including audio waveforms. All six names are first-class `LogicalType` values, not string aliases.

## Types

| SQL type | Storage | Meaning |
| --- | --- | --- |
| `FILE` | `STRUCT(url VARCHAR, content_type VARCHAR, position BIGINT, size BIGINT, checksum VARCHAR)` | Generic immutable object reference with an optional byte window (`position`, `size`) |
| `IMAGEFILE` | Same five fields, `IMAGE` media subtype | Encoded image object |
| `AUDIOFILE` | Same five fields, `AUDIO` media subtype | Encoded audio object |
| `VIDEOFILE` | Same five fields, `VIDEO` media subtype | Encoded video object |
| `IMAGE` | Dynamic `STRUCT(data, channel, height, width, mode)`; fixed `IMAGE(mode, H, W)` is a dense `ARRAY` | Decoded interleaved HWC pixels |
| `TENSOR(dtype, shape)` | Variable rank uses `STRUCT(data LIST, shape INTEGER[rank])`; fully fixed shapes use a dense `ARRAY` | Dense row-major numeric tensor |

Constructors are `file`, `image_file`, `audio_file`, and `video_file` for the `FILE` family, `IMAGE`, `IMAGE('RGB')`, and `IMAGE('RGB', H, W)` for images, and `tensor(data, shape)` for tensors. In Python, `vane.File`, `vane.ImageFile`, `vane.AudioFile`, and `vane.VideoFile` are immutable references with the same five fields, and `vane.image_type()` / `vane.image_type('RGB'[, H, W])` / `vane.tensor_type(dtype, shape)` build the corresponding types.

## IMAGE modes

Pixel dtype follows the mode:

| Modes | Pixel dtype | Channels |
| --- | --- | --- |
| L, LA, RGB, RGBA | UInt8 | 1, 2, 3, 4 |
| L16, LA16, RGB16, RGBA16 | UInt16 | 1, 2, 3, 4 |
| RGB32F, RGBA32F | Float32 | 3, 4 |

Generic `IMAGE` stores Float32 so one column can hold every mode without loss; a known mode stores its native pixel dtype. Fetched cells materialize as C-contiguous NumPy arrays with shape `(height, width, channels)`. Arrow carries fixed-shape images with the `vane.image` extension type.

## Audio specialization

The audio API uses Float64 tensors with shape `(frames, channels)`. Both counts can vary by row; mono is `(frames, 1)`. Channels must be positive, while zero frames (`(0, channels)`) are allowed for empty audio. Resampling returns exactly `ceil(decoded_frames * target_rate / source_rate)` frames, trimmed or zero-padded at the end of the complete stream. Both backends use SoXR HQ.

## Video frame rows

`read_video_frames` emits one row per selected frame. Each row keeps the source `path VARCHAR` and the original `file VIDEOFILE` view plus presentation-order frame metadata (`frame_index`, `frame_time`, `frame_pts`, `frame_dts`, `frame_duration`, `is_key_frame`, time-base fields) and `data: IMAGE('RGB', H, W)` packed RGB uint8 pixels resized to the requested dimensions. Unknown temporal metadata remains `NULL`.

## Python values and errors

- `file.is_image()` / `is_audio()` / `is_video()` classify without I/O, using the declared subtype first, then `content_type` or the URL suffix as a routing hint. `as_image()` / `as_audio()` / `as_video()` return a new value with the same five fields; converting between different media subtypes raises `TypeError`.
- `file.stat()` and `file.exists()` inspect storage without decoding. SQL expression equality requires the same `FILE` subtype and keeps SQL `NULL` semantics.
- A non-`NULL` image requires every field and pixel to be non-`NULL`; width and height must be positive. A non-`NULL` tensor has no `NULL` dimensions or elements; a zero dimension is an empty tensor, distinct from a `NULL` tensor.
